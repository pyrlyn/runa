# docs/ — указатель документации

Всё, что нужно читателю помимо корневого [`README.md`](../../README.md): руководства
пользователя, справочные страницы, инженерные заметки и реестр захвата задач.
Вся проза в этом репозитории пишется на английском, кроме переводов в `docs/ru/` и
`docs/uk/` (см. [`../CONTRIBUTING.md`](../../CONTRIBUTING.md)).

| Кому | С чего начать |
|----------|------------|
| Новому пользователю | [`getting-started.md`](getting-started.md) → [`guide.md`](guide.md) |
| Тому, кто ищет флаг или ключ | [`config.md`](config.md), [`fit.md`](fit.md), [`thinking.md`](thinking.md), [`media.md`](media.md), [`structured.md`](structured.md) |
| Контрибьютору | [`../AGENTS.md`](../../AGENTS.md), [`../CONTRIBUTING.md`](../../CONTRIBUTING.md), [`versions.md`](versions.md) |
| Агенту, берущему задачу | [`tasks.md`](../tasks.md), [`../plan.md`](../../plan.md), [`../AGENTS.md`](../../AGENTS.md) |

## Добавление и изменение документации

1. Проза на английском; соответствующие переводы в `docs/ru/` и `docs/uk/` обновляйте
   в том же изменении. Документируйте то, что дерево действительно поставляет, — никаких
   выдуманных API, флагов или ключей конфигурации.
2. Одна тема на файл, с коротким заголовком H1 — без префикса `docs/<file> —`
   и без кодов плана; H1 — это заголовок страницы на сайте проекта.
3. Добавьте новый файл в этот указатель **и** в таблицу Docs в
   [`../README.md`](../../README.md) в том же изменении.
4. Новому или изменённому публичному методу также нужна запись в [`memory.md`](memory.md)
   (AGENTS.md §5); то же правило относится к любой другой документированной поверхности.
5. Поддерживайте [`tasks.md`](../tasks.md) валидным — `moon run root:lint-tasks`
   (`python3 scripts/lint-tasks.py docs/tasks.md`) должен оставаться зелёным.
6. ADR только дополняются: никогда не переписывайте принятое решение; заменяйте его
   новым ADR, в котором сказано, что именно он заменяет.
