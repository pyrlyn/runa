# Аудио, видео и зрение

Три маршрута, которые никогда не смешиваются молча (D12):

| Маршрут | Локально | OpenAI | Anthropic |
|-------|-------|--------|-----------|
| **native** | mtmd + mmproj для аудио/зрения | `input_audio` на моделях с поддержкой аудио | недоступно |
| **asr** | whisper.cpp (`whisper-rs`) → текст в промпте | транскрипт в промпте | транскрипт в промпте |
| **auto** | native, если есть mmproj (аудио) / VL mmproj (зрение); иначе ASR | `input_audio`, если поддерживается, иначе транскрипт | транскрипт |

## Аудио (`--audio`, `--audio-route`)

Приоритет: CLI `--audio-route` > `RUNA_AUDIO_ROUTE` > `[audio] route` > `auto`.

- **native** без аудио-mmproj (или на Anthropic / OpenAI-моделях без аудио) завершается ошибкой.
- **asr** всегда транскрибирует (`runa media transcribe` использует тот же движок).
- PCM — 16 кГц, моно, f32 (`runa-media`). Нативный маршрут OpenAI оборачивает WAV в base64.

Соседний `*mmproj*.gguf` подхватывается, только когда он нужен нативному аудио или `--image`/`--video`.
Если задан `--mmproj`, побеждает он.

## Зрение (`--image`, `--video`)

Только локально, фича `mtmd` + mmproj для зрения:

- `--image PATH` (можно повторять) — статичные изображения, медиа-маркеры, без временных меток.
- `--video PATH` — `runa-media` выбирает ≤ 32 кадров; каждый становится bitmap mtmd
  с маркером `[t=12.0s]` в промпте.

Облачные `--image`/`--video` в `runa run openai:…` — явная ошибка (используйте
локальную VL-модель или адаптеры P4.7 из `serve`).

## Выборка кадров видео

Равномерная + по смене сцены (L1 по гистограмме), не более 32, с ресайзом. ffmpeg из PATH или
`ffmpeg-sidecar`. См. P4.5.

## Fit

Кадры × токены на кадр + секунды аудио учитываются как контекст; байты mmproj лежат
на GPU. Переполнение → `NO FIT`, код выхода 2 (`docs/fit.md`).
