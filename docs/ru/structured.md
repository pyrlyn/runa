# docs/structured.md — структурированный вывод

`runa` может заставить ответ модели соответствовать JSON Schema или грамматике GBNF.
Локальные модели используют сэмплирование по грамматике llama.cpp, поэтому вывод всегда соответствует.
Модели OpenAI получают схему как `response_format` (`strict: true`).

## CLI

```sh
runa run qwen "Capital of France and its population?" \
  --json-schema '{"type":"object","properties":{"city":{"type":"string"},"population":{"type":"integer"}},"required":["city","population"]}'
runa run qwen "Is Paris in France?" --grammar yes-no.gbnf
```

| Флаг | Значение | Примечания |
| --- | --- | --- |
| `--json-schema` | путь к файлу или встроенный JSON, начинающийся с `{` | Локально, OpenAI и Anthropic (принудительный инструмент, см. ниже). |
| `--grammar` | файл GBNF | Только локально. Конфликтует с `--json-schema`. |

Запрос с ограничениями выключает рассуждение, а также Zig-сэмплер ядер
и n-gram-спекуляцию. Грамматика должна видеть каждый токен.

## `runa serve`

`POST /v1/chat/completions` принимает `response_format` в формате OpenAI:

| `type` | Эффект |
| --- | --- |
| `text` | Без ограничений |
| `json_object` | Любой объект JSON (`{"type":"object"}`) |
| `json_schema` | `json_schema.schema` обязателен; ответ ему соответствует |

Некорректная схема возвращает `400`.

## Вызов инструментов

И `POST /v1/chat/completions`, и `POST /v1/messages` принимают инструменты и
возвращают вызовы в формате соответствующего API:

| | OpenAI | Anthropic |
| --- | --- | --- |
| Инструменты | `tools` (`type: function`) | `tools` (`name`, `input_schema`) |
| Выбор | `auto`, `required`, `none`, `{"function":{"name":…}}` | `auto`, `any`, `none`, `{"type":"tool","name":…}` |
| Вызовы от модели | `message.tool_calls`, `finish_reason: tool_calls` | блоки `tool_use`, `stop_reason: tool_use` |
| Результаты к модели | `role: tool` + `tool_call_id` | блоки `tool_result` |

При стриминге каждый вызов отправляется один раз, когда генерация заканчивается: одна дельта `tool_calls`
для OpenAI и `content_block_start` / `input_json_delta` /
`content_block_stop` на каждый вызов для Anthropic.

Формат вызова определяет чат-шаблон модели (Hermes `<tool_call>`
для Qwen3, Harmony `<|channel|>commentary to=functions.…` для gpt-oss
— покрыто тестом `harmony_tool_reply_parses` на реальном шаблоне 20B —
обобщённый JSON, если шаблон не поддерживает инструменты). `auto`
использует ленивую грамматику, которая включается на триггере формата, поэтому модель
всё ещё может ответить обычным текстом или сначала порассуждать. `required` и именованный инструмент используют
жадную грамматику. Модель без чат-шаблона отклоняет инструменты с кодом `400`.
Инструменты нельзя сочетать с вводом изображений или аудио.

## Цикл инструментов MCP (`run` / `chat`)

```sh
runa run qwen3 "What is the weather in Paris?" --mcp 'python3 weather_server.py'
runa chat qwen3 --mcp 'npx -y @modelcontextprotocol/server-filesystem .'
```

`--mcp '<command args>'` (можно повторять) и `[mcp.servers.<name>]` в конфигурации
(`docs/config.md`) запускают stdio-серверы MCP. Их инструменты передаются модели. Когда
модель вызывает один из них, runa выполняет его на сервере, который его объявил, отправляет
результат обратно сообщением `tool` и снова запускает генерацию. Это повторяется, пока
модель не ответит без вызова или пока не будет достигнут `--max-tool-rounds` (по умолчанию 8),
что считается ошибкой. Каждый вызов логируется в stderr как
`[tool] name(args) -> N bytes`. Неудачный вызов возвращается модели как
текст `error: …`.

| Бэкенд | Как передаются инструменты |
| --- | --- |
| Локальный | Через чат-шаблон, как в `runa serve` выше |
| OpenAI | `tools`, `tool_calls` ассистента, сообщения `role: tool` |
| Anthropic | `tools`, блоки `tool_use` (отправляются обратно целиком, включая рассуждение), блоки `tool_result` |

`--mcp` разбивается по правилам кавычек оболочки (P10.8): `'...'` берётся буквально, `"..."`
допускает экранирование обратной косой чертой, а обратная косая черта вне кавычек экранирует следующий
символ — `--mcp "python3 'my dir/s.py'"` работает. Незакрытые кавычки
считаются ошибкой. Всё более сложное (переменные окружения, `env` для отдельного сервера) задаётся в
`[mcp.servers]`. Два сервера, предлагающие инструмент с одинаковым именем, — ошибка.
Чат хранит историю между ходами (P10.9): каждый ход отправляет весь транскрипт на данный момент, включая раунды инструментов. `/reset` и `/model` очищают её.

Структурированный вывод в Anthropic (`--json-schema`) использует тот же механизм: один
принудительный инструмент `answer`, у которого `input_schema` — это схема. Его входные данные и есть
ответ. Принудительный инструмент выключает рассуждение, и его нельзя сочетать с
`--mcp`.

## Как формируется промпт

Запросы с ограничениями формируются через Jinja-обработчик чата llama.cpp
(`apply_chat_template_oaicompat`). Обработчик знает формат чата модели.
Он возвращает промпт, грамматику, триггеры ленивой грамматики и дополнительные
стоп-строки. Модели без чат-шаблона откатываются к обычному промпту
плюс жадная грамматика. Схемы конвертируются функцией llama.cpp
`json_schema_to_grammar` (`runa_engine::schema_to_grammar`).
