# docs/ — покажчик документації

Усе, що потрібно читачеві понад кореневий [`README.md`](../../README.md): посібники
користувача, довідкові сторінки, інженерні нотатки та реєстр заявок на задачі.
Уся проза в цьому репозиторії англійською, крім перекладів у `docs/ru/` і
`docs/uk/` (див. [`../CONTRIBUTING.md`](../../CONTRIBUTING.md)).

## Додавання або зміна документації

1. Проза англійською; відповідні переклади в `docs/ru/` і `docs/uk/` оновлюйте
   в тій самій зміні. Документуйте те, що дерево справді постачає, — жодних вигаданих API,
   прапорців чи ключів конфігурації.
2. Одна тема на файл, з коротким заголовком H1 — без префікса `docs/<file> —`
   і без кодів плану; H1 — це заголовок сторінки на сайті проєкту.
3. Додайте новий файл до цього покажчика **і** до таблиці Docs у
   [`../README.md`](../../README.md) в тій самій зміні.
4. Новий або змінений публічний метод також потребує запису в [`memory.md`](memory.md)
   (AGENTS.md §5); те саме правило стосується будь-якої іншої задокументованої поверхні.
5. Тримайте [`tasks.md`](../tasks.md) валідним — `moon run root:lint-tasks`
   (`python3 scripts/lint-tasks.py docs/tasks.md`) має лишатися зеленим.
6. ADR лише доповнюються: ніколи не переписуйте прийняте рішення; замініть його
   новим ADR, що вказує, яке рішення він заміщує.
