# Структурований вивід

`runa` може примусити модель відповідати за JSON Schema або граматикою GBNF.
Локальні моделі використовують семплінг за граматикою llama.cpp, тож вивід завжди відповідає.
Моделі OpenAI отримують схему як `response_format` (`strict: true`).

## CLI

```sh
runa run qwen "Capital of France and its population?" \
  --json-schema '{"type":"object","properties":{"city":{"type":"string"},"population":{"type":"integer"}},"required":["city","population"]}'
runa run qwen "Is Paris in France?" --grammar yes-no.gbnf
```

| Прапорець | Значення | Примітки |
| --- | --- | --- |
| `--json-schema` | шлях до файлу або вбудований JSON, що починається з `{` | Локально, OpenAI та Anthropic (примусовий інструмент, див. нижче). |
| `--grammar` | файл GBNF | Лише локально. Конфліктує з `--json-schema`. |

Обмежений запит вимикає міркування, а також семплер на ядрах Zig
і n-грамну спекуляцію. Граматика має бачити кожен токен.

## `runa serve`

`POST /v1/chat/completions` приймає `response_format` OpenAI:

| `type` | Ефект |
| --- | --- |
| `text` | Без обмеження |
| `json_object` | Будь-який об'єкт JSON (`{"type":"object"}`) |
| `json_schema` | `json_schema.schema` обов'язковий; відповідь йому відповідає |

Невалідна схема повертає `400`.

## Виклик інструментів

І `POST /v1/chat/completions`, і `POST /v1/messages` приймають інструменти та
повертають виклики у формі відповідного API:

| | OpenAI | Anthropic |
| --- | --- | --- |
| Інструменти | `tools` (`type: function`) | `tools` (`name`, `input_schema`) |
| Вибір | `auto`, `required`, `none`, `{"function":{"name":…}}` | `auto`, `any`, `none`, `{"type":"tool","name":…}` |
| Виклики назовні | `message.tool_calls`, `finish_reason: tool_calls` | блоки `tool_use`, `stop_reason: tool_use` |
| Результати всередину | `role: tool` + `tool_call_id` | блоки `tool_result` |

Стримінг надсилає кожен виклик один раз, коли генерація завершується: одну дельту `tool_calls`
для OpenAI і `content_block_start` / `input_json_delta` /
`content_block_stop` на кожен виклик для Anthropic.

Формат виклику визначає чат-шаблон моделі (Hermes `<tool_call>`
для Qwen3, Harmony `<|channel|>commentary to=functions.…` для gpt-oss
— покрито тестом `harmony_tool_reply_parses` на справжньому шаблоні 20B —
узагальнений JSON, коли шаблон не підтримує інструменти). `auto`
використовує ліниву граматику, що вмикається на тригері формату, тож модель
усе ще може відповісти звичайним текстом або спершу поміркувати. `required` та іменований інструмент використовують
енергійну (eager) граматику. Модель без чат-шаблону відхиляє інструменти з `400`.
Інструменти не можна поєднувати з вхідними зображеннями чи аудіо.

## Цикл інструментів MCP (`run` / `chat`)

```sh
runa run qwen3 "What is the weather in Paris?" --mcp 'python3 weather_server.py'
runa chat qwen3 --mcp 'npx -y @modelcontextprotocol/server-filesystem .'
```

`--mcp '<command args>'` (можна повторювати) і `[mcp.servers.<name>]` у конфігурації
(`docs/config.md`) запускають stdio-сервери MCP. Їхні інструменти передаються моделі. Коли
модель викликає один із них, runa виконує його на сервері, який його оголосив, надсилає
результат назад як повідомлення `tool` і генерує знову. Це повторюється, доки
модель не відповість без виклику або доки не буде досягнуто `--max-tool-rounds` (типово 8),
що є помилкою. Кожен виклик логується в stderr як
`[tool] name(args) -> N bytes`. Невдалий виклик повертається моделі як
текст `error: …`.

| Бекенд | Як передаються інструменти |
| --- | --- |
| Локальний | Чат-шаблон, як у `runa serve` вище |
| OpenAI | `tools`, `tool_calls` асистента, повідомлення `role: tool` |
| Anthropic | `tools`, блоки `tool_use` (надсилаються назад повністю, разом із міркуванням), блоки `tool_result` |

`--mcp` розбивається за правилами екранування shell (P10.8): `'...'` — буквальний рядок, `"..."`
дозволяє екранування зворотною скісною рискою, а зворотна скісна риска поза лапками екранує наступний
символ — `--mcp "python3 'my dir/s.py'"` працює. Незакриті лапки
є помилкою. Усе складніше (змінні середовища, `env` для окремого сервера) задається в
`[mcp.servers]`. Два сервери, що пропонують інструмент з однаковою назвою, — помилка.
Чат зберігає історію між ходами (P10.9): кожен хід надсилає весь дотеперішній транскрипт, включно з раундами інструментів. `/reset` і `/model` очищають її.

Структурований вивід Anthropic (`--json-schema`) використовує той самий механізм: один
примусовий інструмент `answer`, чий `input_schema` і є схемою. Його вхід — це
відповідь. Примусовий інструмент вимикає міркування, і його не можна поєднувати з
`--mcp`.

## Як це рендериться

Обмежені запити рендеряться через обробник чату Jinja з llama.cpp
(`apply_chat_template_oaicompat`). Обробник знає чат-формат моделі.
Він повертає промпт, граматику, тригери лінивої граматики та додаткові
стоп-рядки. Моделі без чат-шаблону повертаються до звичайного промпту
з енергійною граматикою. Схеми конвертуються функцією llama.cpp
`json_schema_to_grammar` (`runa_engine::schema_to_grammar`).
